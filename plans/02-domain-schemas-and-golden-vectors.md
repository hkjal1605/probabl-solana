# Milestone 02 — Domain schemas and golden vectors

## Implementation status — 2026-09-04

Core enums, structs, EIP-712 schema, market identity, and bigint rounding are implemented in Solidity and `packages/domain`. `fixtures/golden-vectors.json` is reproducibly generated by TypeScript and consumed by both Bun and Foundry tests for market/question/condition IDs, order hashes, and quote rounding. CTF position IDs are verified against the pinned CTF in integration tests; a TypeScript implementation of Gnosis's elliptic-curve collection-ID derivation is deliberately not duplicated.

## Goal

Define one language-independent protocol model for market identity, orders, amounts, claims, states, events, and payout previews before contract or service implementations diverge.

## Dependencies

- Milestone 01 repository and ADR foundation.

## Domain definitions

Define in Solidity interfaces and `packages/domain`:

- `MarketId`, `ConditionId`, `QuestionId`, `OrderHash`, token addresses, and position IDs.
- `Branch { YES, NO }`.
- `Side { BUY, SELL }`.
- `FundingKind { WHOLE_COLLATERAL, ACTIVE_CLAIM }`.
- `TimeInForce { GTC, IOC }`.
- Market lifecycle: `Draft`, `Scheduled`, `Open`, `Frozen`, `AwaitingResolution`, `Resolved`, `Redeemable`, `Archived`.
- Order lifecycle: prepared, submitted, open, partially filled, filled, cancel-pending, canceled, expired, rejected, and settlement-pending projections.
- Resolution vectors: YES `[1,0]/1`, NO `[0,1]/1`, invalid `[1,1]/2`.

## Immutable market identity

Specify byte-for-byte encoding for:

```text
keccak256(
  protocolVersion,
  robinhoodChainId,
  baseStockToken,
  quoteToken,
  polygonChainId,
  polymarketConditionId,
  polymarketYesIndex,
  polymarketNoIndex,
  tradingOpen,
  tradingCutoff,
  rulesHash
)
```

Document Solidity ABI encoding choices and equivalent TypeScript code. Never hash display titles or mutable URLs as identifiers.

## EIP-712 order schema

Freeze the v1 typed-data domain and order fields:

```text
maker
recipient
marketId
branch
side
fundingKind
quantity
limitPriceRawX18
tif
expiry
nonce
salt
```

Specify chain ID and exchange-address domain separation, supported signature types, nonce behavior, expiry boundaries, and replay rules.

## Amount and rounding rules

- Raw integers only; no floating point.
- V2 supersedes the historical 18-decimal registration restriction: use raw-unit-ratio prices, versioned signatures and exact offchain decimal metadata. Test mixed-decimal pairs and reject legacy payloads.
- Use `priceX18` and full-precision `mulDiv`.
- Round bid reservation up.
- Round execution transfer down to the smallest quote unit.
- Define tick, base step, minimum notional, maximum dust, and overflow rejection.
- Keep collateral accounting in raw Stock Token units; multiplier application is display-only unless official token mechanics require otherwise.

## Golden vectors

Create machine-readable vectors covering:

- market IDs and local CTF question/condition IDs;
- YES/NO position IDs for stock and USDG;
- EIP-712 domain separators, struct hashes, digests, and signatures;
- quote calculations across decimal combinations and boundary values;
- reservation versus execution rounding;
- maker-price selection from canonical sequence;
- full and partial fill accounting;
- all four funding combinations;
- YES, NO, and invalid redemption previews;
- nonce invalidation and expiry boundaries.

Every vector must include inputs, intermediate normalized values, expected raw outputs, and human-readable outputs.

## Deliverables

- Versioned domain schema package.
- Solidity interfaces/types package.
- JSON golden-vector fixtures.
- TypeScript vector generator/checker.
- Solidity tests consuming the same committed fixtures.
- Short protocol glossary.

## Exit criteria

- [ ] Solidity and TypeScript produce identical market IDs, order hashes, position IDs, and amounts.
- [x] No accounting code uses JavaScript `number` or floating point.
- [x] Boundary, overflow, dust, and rounding behavior is explicit and tested.
- [x] Schema versioning and backward-compatibility rules are documented.
- [x] Manual-resolution states exist; attestation or cross-chain fields do not.
- [x] No identity/KYC field appears in the order or claim schema.

## Non-goals

- Deploying contracts.
- Persisting database records.
- Matching live orders.
- Adding future order types or multiple quote tokens.
